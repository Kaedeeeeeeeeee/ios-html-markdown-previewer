英文关键词候选：

这些词来自已实现的功能与文件类型，是待验证的搜索假设。本次未取得单个搜索词的搜索量或排名，不将词表称为已验证最优方案。PDF 指 HTML/Markdown 导出，LaTeX 指 Markdown 数学公式，不能延伸成 PDF 文件阅读器或完整 TeX 编译器。

| 要覆盖的需求 | 候选中的表达 |
|---|---|
| HTML 文件查看 | 产品名中的 HTML、副标题中的 Viewer、关键词中的 file/htm |
| Markdown 阅读 | 副标题中的 Markdown、关键词中的 reader/md/readme |
| JSON 查看 | 副标题中的 JSON 和 Viewer |

| 公式与流程图 | 关键词中的 math/latex/mermaid |

这张表解释文案覆盖的意图，不承诺 Apple 会按指定方式组合索引或赋予排名。

推广文本与描述先讲“打开报告、阅读 Markdown、查看 JSON/YAML”，再清楚说明文件本地处理、付费下载、无广告和无订阅。Apple 明确说明推广文本不影响搜索排名；它主要用于购买说明。JSON/YAML 只读、PDF 格式边界和 HTML 外部资源行为继续准确描述。[Apple 产品页指引](https://developer.apple.com/app-store/product-page/)

将本轮作为一套元数据变更记录。副标题与关键词需要通过下一可编辑版本的流程；繁中是否可新增及后台字段是否可编辑，应在实际应用时核查。提交前复制候选中的字段到该版本的正式元数据来源，按项目既有流程做后台 read-back。保存本地差异、最终字段和商店公开生效日期。

## 评价入口：核验现有本地实现

本方案准备期间，工作区出现了另一份评分提示实现。本次已只读核对其控制器、SwiftUI 请求视图和 [实现说明](../../updates/2026-10-03-review-prompts.md)，没有修改评分功能代码，也没有将其构建或测试结果计入本次文案校验。

当前实现门槛为：完成 5 次阅读，跨至少 3 个本地日，每次内容就绪后在前台阅读至少 30 秒；内置示例不计。返回文件列表停留 2 秒后才调用系统请求，导入、搜索、分享、加载、后台等状态不触发。每个营销版本最多尝试一次，间隔至少 120 天，记录只保存在本地。StoreKit 决定是否实际显示，代码不能证明用户已经评分。

下一步接续该功能原有的构建、回归与交付验收，特别核验延后/取消、样例排除、前后台时间和限频，然后随正常版本交付。避免重复实现，也不要将评价数的变化混作元数据优化的单独效果。

## 如何判断有效

1. 记录这次组合变更真实公开生效日期、版本、四语言字段、截图顺序、价格和推广活动，等 Apple 数据覆盖完整日期后再比较。
2. 每 7 天看方向，满 30 个完整 UTC 日复核，与同样长度的前一窗口比较。若新版生效前没有完整基线，标记这一限制，不把旧版本功能差异当成单个字段的效果。
3. 主指标为 App Store Search 曝光日均、搜索来源首次下载；同时记录搜索转化率、产品页浏览和地区分布。首次下载与重新下载分开记录，沿用 Apple 的转化率口径。
4. 可先设运营目标：搜索曝光日均从 11.4 提高到 20–25，搜索首次下载从每 30 天 3 次增加到 6 次以上。这是工作目标，不是效果预测或统计显著性标准。
5. 曝光增加而下载未跟上时，继续研究匹配的搜索意图和截图说明；曝光仍少时，再调整词表。个位数下载的波动不足以宣布方案成功或失败。
6. 上线观察期间保持清楚的变更记录。没有随机对照的前后比较只能提供方向，不能证明关键词、副标题或截图中某一项导致变化。
